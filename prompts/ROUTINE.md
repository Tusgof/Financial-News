# ROUTINE — รัน 1 ครั้งต่อวัน เพื่อสร้างข่าวลงเว็บ (single combined routine)

> นี่คือ "พรอมต์รวม" สำหรับตั้งเป็น Claude Routine ตอนเช้าทุกวัน
> รันชุดนี้ชุดเดียวจบ: หาข่าว 3 หมวด → เขียนไฟล์ → อัปเดต manifest → เตรียม commit
> อิงสัญญารูปแบบกับ `assets/js/app.js` และคู่มือใน `README.md`

---

## ทำไมต้อง "1 routine" ไม่ใช่ "3 routines"

ใช้ **routine เดียว** เพราะ:
1. เว็บอ่านข้อมูลทั้งวันจาก `news/<วันที่>/` 3 ไฟล์ + `manifest.json` 1 ไฟล์ — ต้องอัปเดต "พร้อมกันทั้งชุด" ถ้าแยก 3 routine จะเกิดสภาพวันที่ขึ้นครึ่งเดียว (เช่น business มา แต่ economy ยังไม่มา)
2. `manifest.json` เป็นไฟล์เดียวที่ทั้ง 3 หมวดต้องเขียน — แยก routine = แย่งเขียน/ทับกัน (git conflict)
3. การจัดอันดับข้ามหมวด (synthesis) ทำได้ก็ต่อเมื่อ "กระบวนการเดียวเห็นครบ 3 หมวด"
4. commit/push ครั้งเดียวต่อวัน = ประวัติ git สะอาด ย้อนได้ง่าย

> ถ้าจำเป็นต้องแยกจริง ๆ (เช่นเวลารันต่างกันมาก) ค่อยแยกเป็น 3 แล้วให้ "routine สุดท้ายของวัน" เป็นคนแตะ manifest + push คนเดียว แต่โดยดีฟอลต์ — รวมเป็น 1 ดีกว่า

---

## ลำดับงานที่ routine ต้องทำ (ตามคู่มือ README)

ตั้งวันที่ = วันนี้ (เวลาไทย) รูปแบบ `YYYY-MM-DD` เรียกว่า `<DATE>`

### ขั้น 1 — หาข่าว + เขียน 3 หมวด
ทำ 3 หมวดตามพรอมต์เฉพาะทาง โดยยึด `00-shared-core.md` เป็นกติกากลางทุกครั้ง:
- หมวดธุรกิจ → ใช้ `01-business.md` → ได้เนื้อหาไฟล์ `business.md`
- หมวดเศรษฐกิจ → ใช้ `02-economy.md` → ได้เนื้อหาไฟล์ `economy.md`
- หมวดการเมือง → ใช้ `03-politics.md` → ได้เนื้อหาไฟล์ `politics.md`

แต่ละไฟล์ต้องมี 2 ส่วน (🌍 Global Top 3 + 🇹🇭 Thailand Top 3) และฟอร์แมตการ์ดตรงสเปกใน core เป๊ะ
(เพราะ `app.js` จับ `### N)`, `**ความเชื่อมั่น:** สูง/กลาง/ต่ำ`, `**ที่มา:** [..](url)`)

### ขั้น 2 — บันทึกไฟล์
เขียนไฟล์ทั้ง 3 ลงโฟลเดอร์ของวันนั้น (สร้างโฟลเดอร์ถ้ายังไม่มี):
```
news/<DATE>/business.md
news/<DATE>/economy.md
news/<DATE>/politics.md
```

### ขั้น 3 — อัปเดต manifest (สำคัญที่สุดสำหรับเว็บ)
เพิ่ม `<DATE>` ไว้ **บนสุด** ของ `news/manifest.json` (ใหม่สุดอยู่บน):
```json
{ "dates": ["<DATE>", "...วันก่อนหน้า..."] }
```
- ถ้ามี `<DATE>` อยู่แล้ว (รันซ้ำวันเดิม) **ห้ามเพิ่มซ้ำ** — แค่ทับไฟล์ .md 3 ไฟล์
- `app.js` อ่าน `MANIFEST_URL = 'news/manifest.json'` แล้วโชว์วันล่าสุดก่อน ถ้าไม่อัปเดต manifest เว็บจะไม่เห็นวันใหม่

### ขั้น 4 — นำขึ้น git (ต้องให้ผู้ใช้ยืนยันก่อน push)
```bash
git add news/
git commit -m "news: <DATE>"
git push
```
> ⚠️ `git push` คือการเผยแพร่ขึ้น remote สาธารณะ — เป็น action ที่ต้อง **ขออนุญาตผู้ใช้ก่อนทุกครั้ง**
> routine ควรหยุดที่ขั้น commit แล้วถามผู้ใช้ก่อน หรือให้ผู้ใช้กดรันคำสั่ง push เอง

## ตรวจก่อนจบ (Checklist)

- [ ] มีครบ 3 ไฟล์ใน `news/<DATE>/`
- [ ] แต่ละไฟล์มีหัวเรื่องตรงสเปก + 2 ส่วน (🌍/🇹🇭)
- [ ] ทุกการ์ดมี `**ความเชื่อมั่น:**` ลงท้าย สูง/กลาง/ต่ำ และ `**ที่มา:**` เป็นลิงก์จริง
- [ ] `manifest.json` มี `<DATE>` อยู่บนสุด ไม่ซ้ำ
- [ ] เปิดเว็บเช็กว่าวันใหม่ขึ้นและการ์ดเรนเดอร์ถูก

## ถ้าจะเปิดหน้า briefing (ตัวเลือกเสริม — ปกติไม่ต้องทำ)

พรอมต์ `04-synthesis.md` จะปั้นไฟล์สรุปรวม `news/<DATE>/briefing.md` (Top ข้ามทั้ง 3 หมวด)
ค่าเริ่มต้นเว็บ **ไม่แสดง** หน้านี้ ถ้าอยากให้โผล่บนเว็บต้องแก้ 1 จุด:

ใน `assets/js/app.js` บรรทัด 10:
```js
const CATEGORIES = ['business', 'economy', 'politics'];
```
เปลี่ยนเป็น:
```js
const CATEGORIES = ['briefing', 'business', 'economy', 'politics'];
```
แล้ว routine ต้องเขียน `news/<DATE>/briefing.md` เพิ่มอีกไฟล์ในขั้น 2

> ข้อดี: ได้หน้า "ข่าวเด่นรวมประจำวัน" ไว้บนสุด
> ข้อเสีย: เพิ่มงาน 1 ไฟล์/วัน + ต้องดูแล parser เพิ่ม
> คำแนะนำ: ถ้ายังไม่ค่อยได้ใช้ — **ข้ามไปก่อน** เก็บ `04-synthesis.md` ไว้เป็นออปชัน รันเฉพาะวันที่อยากได้สรุปพิเศษ
